# 训练与标杆数值不一致

> 能力等级 **C**。前提是你有一个可信的参考实现（CPU fp32 或另一个硬件平台）。没有标杆时这个领域不成立，见第三节。

## 一句话结论

**训练级验收门槛和算子级比对门槛是两套不同的东西，混用会同时产生大量假警报和漏判**——逐层比对只用来定位首个异常点，判定通过与否只能用训练级指标；而所有阈值都应该用参考平台自己的噪声底线来校准，不是照抄别人的数字。

## 当前状态

**待建设。** 没有工具时只能看 loss 曲线级别的东西——能知道"对不上"，不能知道"从哪一层开始对不上"。而这个领域 90% 的工作量就在后半句。

需要[精度工具栈](_precision-toolchain.md)建到**阶段 2**（按调用实例对齐的比对）才完整可用。阶段 3 的完整张量 dump 用于读出第四节那些真因的"指纹"。

## 一、两种门槛不能混用

这是本文最重要的一节。**算子级门槛**问的是"这一次算子调用，目标平台和参考实现的输出差多少"；**训练级门槛**问的是"这个模型在目标平台上训练，和在参考平台上训练，是不是在做同一件事"。差别不只是数值松紧，而是**背后的误差模型根本不同**。

### 四个结构性差异

| 维度 | 算子级 | 训练级 |
|------|--------|--------|
| 误差是否累积 | 单次调用，一次性 | 上千算子串联 × 上千步迭代，累积与衰减并存 |
| 两侧输入是否相同 | 可以保证逐位相同（把同一份输入喂给两边） | **做不到**。第一步之后两边权重已经不同 |
| 判定对象 | 实现是否正确，二元的，错了就要修 | 训练是否等价，统计性的，每步数值都不同也可能通过 |
| 容忍度的来源 | 可从 dtype 和运算次数推算（舍入误差上界） | 只有经验，没有理论推导 |

第二行值得展开。算子级比对里，两侧算的是**同一个计算的两种实现**，差异只能来自实现。训练级比对从第二步开始就不是这样了——第一步的微小差异改变了权重，第二步的输入随之不同，之后每一步比的都是**两条已经分叉的轨迹**。这是为什么训练级门槛必须随步数放宽，而算子级门槛不需要；也是为什么"第 500 步的 loss 差了 1%"不能直接当成"有 1% 的实现误差"。

第四行同样重要。算子级的容忍度有理论依据：一个归约长度为 K 的操作，舍入误差大致随 K 或 sqrt(K) 增长（取决于归约树形状），结合 dtype 的机器 epsilon 就能估出合理范围。所以"fp16 累加的 GEMM 相对误差 1e-3 量级"是可以推算的，不是拍的。训练级没有这种推导，只有"历史上这个误差水平下模型收敛到了同样的指标"。

### 混用的两种典型错误

**拿算子级阈值卡训练。** 常见做法是要求每一层输出的相对误差都 < 1e-3。结果一个 32 层模型跑下来，第 20 层之后必然全部超标——因为误差在逐层累积，这是**数学必然而不是 bug**。团队于是在一屏红色告警里浪费时间，几次之后就开始忽略告警，工具失去意义。

正确的做法是：**逐层比对只用于定位首个异常点，不用于判定通过与否**。它的输出应该是"误差从第几层开始偏离预期的累积曲线"，而不是"有 12 层超标"。判定通过与否用训练级指标。

**拿训练级阈值卡算子。** 某个算子输出相对误差 2%，但 loss 曲线仍然重合，于是判定"这个算子没问题"。这很危险——对一个 GEMM 来说 2% 是巨大的误差，几乎一定意味着实现错误（最常见的是累加器用了 fp16 而不是 fp32），只是当前这个模型恰好不敏感。换个模型、换个超参、训得更久，它就会暴露，而那时已经没人记得这里放过一马。

### 首步是特殊的

在 step 0，两边权重完全相同、输入完全相同，**这是唯一一步可以做严格比对的**。首步的 loss 相对误差基本上就是前向路径累积误差的直接度量，不掺任何轨迹分叉的成分。所以它的门槛应当显著紧于后续步骤，必须在门槛表里单独列一行。如果首步就差得多，后面的步数不用看了——先回到第五节的分步对齐顺序。

## 二、训练级门槛参考值

| 指标 | 参考门槛 | 说明 |
|------|---------|------|
| 首步 loss 相对误差 | < 1e-3（bf16/fp16 混精）<br>< 1e-5（纯 fp32） | 唯一能严格比的一步 |
| 前 10 步 loss 相对误差 | < 1e-2 | 轨迹刚开始分叉 |
| 全程平均 loss 相对误差 | < 2% | 取比对区间内逐步相对误差的平均 |
| loss 误差的**趋势** | 在 0 附近震荡，无单边漂移 | 见下文，这一条比幅度更重要 |
| 首步梯度范数相对误差 | < 1e-2 | 反向的累积误差大于前向，门槛相应放宽 |
| 全程平均梯度范数相对误差 | < 5% | — |
| 最终指标（ppl / 下游任务） | 落在参考实现的正常波动范围内 | 终极验收，但反馈周期最长 |

**这些数字是行业里常见的量级，不是标准。** 它们依赖于模型规模与深度（层数越多累积越大）、使用的精度（纯 fp32 可以紧一两个数量级）、优化器（Adam 的自适应缩放对梯度幅值差异有一定吸收能力，SGD 没有）、训练阶段（warmup 期 loss 下降快，相对误差天然大；收敛后期 loss 变化小，相对误差对噪声更敏感）、以及是否存在 loss spike（有 spike 的区间不能参与平均，否则一个 spike 就能让平均值毫无意义）。

### 比照抄数字更可靠的做法：用噪声底线校准

在参考平台上用**两个不同的随机种子**各跑一遍，得到的差异就是这个模型在这个配置下的**噪声底线**。目标平台与参考平台的差异如果不超过噪声底线的若干倍，就是可接受的。

这个方法的好处是它自动吸收了上面列的所有依赖因素——模型规模、精度、优化器、训练阶段的影响全部体现在噪声底线里了，不需要你一项项调整阈值。而且它给出的是一个有意义的参照：**如果两个种子之间的差异比跨平台差异还大，那么跨平台差异根本不值得查**。

同样的思路还有一个变体，用来区分"并行配置引起的正常数值差异"：在参考平台上改变 DP 规模（比如 8 卡 vs 4 卡配梯度累积 2，保持全局 batch 不变），测出的差异就是归约顺序变化带来的正常波动量级。

建议把第一个表当作起点，在项目早期就用噪声底线校准一次，然后把校准后的值写进 CI。

## 三、前置条件

下面三条是**硬门槛**，不满足就不要开始比对，否则会在无法归因的现象上浪费大量时间。

**一、没有可信标杆就不要做比对。** "可信"的要求是：参考实现本身正确（有人用它训出过正常的模型）、能跑同样的模型和配置、能导出可比的中间量。CPU fp32 是最常见的选择——精度高、确定性好，缺点是慢到只能跑极小规模。用另一个硬件平台做标杆的话，要先确认那个平台自己是对的，否则你在对齐两个都不确定的东西。

没有标杆时，**正确的做法不是降低标准硬比，而是转向自洽性检查**：梯度数值检验（有限差分与反向传播对比，在小模型上可行）、单 batch 过拟合（一个 batch 反复训，loss 应当能压到接近 0；压不下去说明反向有问题）、与解析解已知的简单算例对比、不同精度自比（fp32 跑一遍、bf16 跑一遍，差异应当在预期范围内）。这些都不需要外部标杆。

**二、目标侧自己都不可复现，就先去解决可复现性。** 两次运行自己就不一样时，与标杆的差异里有多少是真实现问题、有多少是随机抖动，无法区分。而且逐层比对要求两侧调用序列可对齐，不可复现往往意味着序列本身在变。转去[训练结果不可复现](train-precision-determinism.md)。

**三、出现 NaN 先去解决 NaN。** NaN 的传染性让所有比对指标失去意义——含 NaN 的相对误差计算结果还是 NaN 或 inf，比对器会报满屏超标但没有一条有用。转去[训练出现 NaN / Inf](train-precision-nonfinite.md)。

另有两条软前提，不满足的话结论不可归因：

**四、两侧配置必须严格一致**——模型超参、并行配置、数据顺序、优化器超参、精度策略。并行配置尤其要注意：TP=2 和 TP=1 在数学上就是**不同的归约顺序**，不是同一个计算，它们之间有差异是正常的，拿来当标杆对齐的参照会得到错误结论。

**五、两侧初始权重必须逐位相同。** 从同一个 checkpoint 加载，不要各自初始化——跨平台的初始化 RNG 路径通常无法保证一致，而初始权重的任何差异都会让后面所有比对失去意义。

## 四、常见真因与它们的指纹

关键的判断纪律是：**先看误差的量级，再看误差的结构**。量级告诉你是不是精度问题（接近机器 epsilon = 正常，1e-3 = 可疑，1e-1 = 几乎一定是实现错误）；结构——误差出现在哪些位置、随什么变化——告诉你是哪一类问题。只看量级不看结构会漏掉大量线索，而这些线索往往比量级本身更能直接指向原因。

| 真因 | 指纹 | 验证方法 |
|------|------|---------|
| **中间精度 / 累加器不同** | 误差随归约长度 K 增长；GEMM 相对误差在 1e-3~1e-2（fp16 累加的典型值）而非 1e-6；误差随机分布、无空间结构 | 固定输入跑单个 GEMM 与 fp32 参考比；查你的 GEMM 是否默认 fp32 累加 |
| **累加顺序不同** | 误差极小（机器 epsilon 乘 sqrt(K) 量级），但稳定存在、无法消除；换 rank 数或 tiling 误差就变 | **这是不可消除的正常现象**。确认它在 epsilon 量级即可，不要试图消灭它 |
| **融合算子语义差异** | 误差集中在某一类层（全部 LayerNorm，或全部 SwiGLU），其它层正常；量级显著大于 epsilon | 把融合算子换成朴素 PyTorch 实现看误差是否消失。常见差异：eps 加在 sqrt 内还是外、是否省略了某个中间 cast、是否用了近似 |
| **GELU 的 tanh 近似 vs 精确 erf** | 误差集中在所有激活层，量级 1e-3 左右 | 值得单列，因为太常见。这两种 GELU 是**不同的函数**，差异不是精度问题而是语义问题。必须确认两侧用的是同一种 |
| **数学库近似实现** | 误差集中在特定逐元素函数（erf / tanh / exp / rsqrt）；误差大小**与输入值相关**，在函数的某些区间大、某些区间小 | 对该函数做输入扫描：在典型取值区间上取密集点画两边的差异曲线。近似实现的误差曲线有特征形状（分段、周期性起伏） |
| **张量布局转换损失** | 误差在某些 shape 上出现、某些 shape 上没有；与 shape 的对齐性相关（如 K 不是 16 倍数时出现） | 扫描不同 shape。布局转换本身不该有损失，有损失说明 padding 处理错误或转换时发生了意外的 cast |
| **集合通信算法差异** | 只在跨 rank 归约之后出现；单卡比对正常、多卡不正常；量级随 rank 数增长 | 先单卡跑一遍作对照；把 all-reduce 换成手工 gather + 单 rank 求和 + broadcast |
| **mask / padding 处理差异** | 误差集中在序列尾部位置或 batch 中较短的样本上，有效位置正常 | 用等长无 padding 的输入跑一遍 |
| **RoPE 实现差异** | 误差随位置索引增长，前几个 token 正常 | 查 interleaved 与 half-split 两种排列约定——这两种实现互不兼容，不是精度问题 |
| **dtype 隐式提升差异** | 某算子在一边自动提升到 fp32、另一边没有 | 比对两侧中间张量的 **dtype** 而不只是数值。这是 dump 要记录元信息的理由之一 |
| **权重加载时的转置或排列** | 误差巨大（不是精度级，是完全不同的值），集中在特定层 | 这其实是接入 bug 不是精度问题，应当在比对开始之前就被发现 |

前两行的对比值得特别注意，因为它们最容易混淆：**累加顺序不同**产生的误差是不可消除的正常现象，而**累加器精度不同**产生的误差是实现缺陷。两者都表现为"GEMM 输出有差异、无空间结构"，区分它们**只能看量级**——epsilon 量级是前者，1e-3 量级是后者。这是"先看量级"这条纪律最有价值的应用场景。

## 五、自研芯片首次做标杆对齐的典型顺序

设计原则是：**每一步的失败都能被明确归因，且前一步通过是后一步的前提**。跳步的代价是在一个复合的差异面前束手无策——你不知道看到的差异是哪一层引入的。

| 步骤 | 比什么 | 能抓出什么 | 门槛类型 |
|------|--------|-----------|---------|
| 1 | **单算子**：固定输入，与 CPU fp32 比 | 算子实现错误、累加精度、近似函数 | 算子级（紧） |
| 2 | **单层前向**：一个 transformer block | 层内组装错误（算子顺序、残差位置、漏掉 scale） | 算子级（略松） |
| 3 | **全模型单步前向**：比 logits | 层间连接问题（embedding、位置编码、最终 norm、lm_head） | 介于两者之间 |
| 4 | **单步反向**：比各参数梯度 | 反向实现问题 | 比前向放宽 |
| 5 | **单步完整迭代**：比更新后的权重 | 优化器实现（bias correction、weight decay 是否解耦、eps 位置） | 同上 |
| 6 | **多步训练（单卡）**：比 loss 曲线 | 累积性问题 | 训练级 |
| 7 | **多卡**：逐个引入 DP / TP / PP | 通信相关问题 | 训练级 |
| 8 | **长程**：比最终指标 | 一切残余问题 | 训练级 |

几点说明：

**第 1 步是唯一能用紧阈值的地方**，因为输入完全可控、没有累积。重点覆盖 GEMM（扫不同 M/N/K，尤其是 K 很大的）、softmax、LayerNorm/RMSNorm、激活函数、attention。

**第 3 步的失败要先区分两种情况**：如果单层（第 2 步）通过而全模型不通过，要么是层间连接有问题，要么只是正常的逐层累积。用"误差是否随层数单调增长"来区分——单调增长是累积，某一层突然跳变是真问题。

**第 4 步比梯度范数而不是逐元素。** 到反向这一步，逐元素对齐已经很困难，范数是更稳健的指标。反向比前向更容易出问题，因为反向算子通常测试得更少。

**第 7 步每加一种并行方式单独验证一次。** 先 2 卡 DP，确认梯度 all-reduce 后两边一致；再加 TP；再加 PP。一次加两种，出了问题无法归因。

两条流程层面的建议：

**第 1、2 步应当做成自动化的算子一致性测试套件，纳入算子库的 CI。** 这比在模型层面反复做比对的性价比高得多——算子级问题在模型层面表现为"某几层误差偏大"，追回去还是得回到算子。模型级比对应当只用于发现"组装"层面的问题。

**每一步通过时的产物要存档作为基线。** 这套东西最终应该变成 CI 里的回归测试，而不是一次性的人工验证。否则下次算子库一升级，全部重来。

## 六、有工具和没工具的差别

**没有工具能做：** 第 1、2 步（手工构造输入手工比，很累且没有覆盖率保证）；第 3 步的 logits 比对（就一个点）；第 6 步的 loss 曲线比对。

**没有工具做不了：** 第 3 到 5 步里的"差异从哪一层开始"——而这恰恰是整个流程里最需要帮助的地方；多卡下的定位；误差随层数的增长曲线（没有它就无法区分"累积"和"某层出错"）。

**有工具后：** 第 3~5 步变成一条命令——两边各跑一步，开 module 级摘要采集，比对器输出首个超阈值的层以及误差随层数的曲线；定位到层之后可以下钻到 API 级，再下钻到完整张量读第四节的指纹。

## 七、需要你拍板的问题

| # | 问题 | 回答后能解锁 |
|---|------|------------|
| 1 | 标杆是什么——CPU fp32、另一个硬件平台、还是没有？ | 决定这个领域是否成立。没有标杆时要先转向第三节的自洽性检查，整个建设优先级要重排 |
| 2 | 标杆平台能跑多大规模（层数、batch、seq）？ | 决定第五节第 3~5 步在什么规模上做，以及能否覆盖真实训练配置 |
| 3 | 你的 GEMM 默认用什么累加精度？有没有办法强制 fp32 累加？ | 排除最常见的一类系统性误差。这一条的答案往往能直接解释掉大半的误差 |
| 4 | 融合算子（RMSNorm、SwiGLU、FlashAttention 类）有没有可切换的朴素实现作为对照？ | 融合算子语义差异的验证手段。没有对照实现就只能靠读代码 |
| 5 | 逐元素数学函数（exp / erf / tanh / rsqrt）用的是精确实现还是近似？近似的误差界是多少？ | 激活层误差的解释依据，以及算子级门槛该定多少 |
| 6 | 有没有算子级一致性测试套件？覆盖了哪些算子？ | 决定标杆对齐从第几步开始，以及第 1、2 步要补多少 |
| 7 | 训练级门槛由谁定、按什么项目校准？能否接受用"参考平台双种子噪声底线"作为校准方法？ | 把第二节的参考值替换成项目实际值，并把它写进 CI |
| 8 | 两侧能否从同一个 checkpoint 加载初始权重？ | 第三节的软前提五。做不到的话所有逐层比对的结论都要打折 |

## 八、知识来源

- **IEEE 754** 浮点标准：机器 epsilon 的定义、浮点加法不满足结合律（累加顺序差异的根本原因）、fp32 / fp16 / bf16 的指数与尾数位分配
- **Nicholas J. Higham**, *Accuracy and Stability of Numerical Algorithms* (SIAM, 2nd ed.)：归约操作误差随归约长度增长的分析，以及不同归约树形状（顺序累加 vs 成对归约）的误差界差异——"误差多大算正常"这一判断的理论依据
- **David Goldberg**, *What Every Computer Scientist Should Know About Floating-Point Arithmetic* (1991)
- **NVIDIA 公开文档**：*Floating Point and IEEE 754 Compliance for NVIDIA GPUs*（FMA 对舍入的影响、不同架构与库版本间结果可能不同的说明）；cuBLAS 关于累加精度与 `math mode` 的文档；NCCL 关于结果依赖所选算法与拓扑的说明
- **Hendrycks & Gimpel**, *Gaussian Error Linear Units (GELUs)* (2016)：精确 erf 形式与 tanh 近似形式的定义——两者是不同函数这一事实的出处
- **Su et al.**, *RoFormer: Enhanced Transformer with Rotary Position Embedding* (2021)：RoPE 的定义；interleaved 与 half-split 两种排列约定的差异来自各开源实现的工程选择
- **Dao et al.**, *FlashAttention* (2022) 及后续版本：融合 attention 的在线 softmax 与分块归约，是"融合算子语义差异"的典型场景
- **PyTorch 官方文档**：`torch.allclose` / `torch.testing.assert_close` 的 rtol/atol 默认值按 dtype 分档的设计——算子级门槛按 dtype 分档这一做法的参照；`torch.autograd.gradcheck`（有限差分梯度检验，无标杆时的自洽性检查手段）
