# 端侧部署

## 一句话结论

**除非你有端侧产品线，这个领域不必建。** 它和本仓库其余 20 个领域不共享任何基础——不是「换个芯片要重写」的程度，而是整条技术栈、整套方法论都不一样。如果你确实要做端侧，正确的做法是另起一个 skill 体系，而不是把云侧的内容改一改。

## 为什么不能复用云侧的内容

本仓库其余所有 skill 都建立在一个共同前提上：**模型跑在 PyTorch 里，有 Python 运行时，可以在线改代码、插 hook、重新编译**。几乎每条方法论都依赖这个前提——性能拆解靠 profiler 在进程内采集，精度诊断靠在模块上挂 hook，图模式靠 Dynamo 在运行时捕获，运行时调试靠插同步点做二分。

端侧把这个前提整个拿掉了。

| 维度 | 云侧（本仓库其余领域） | 端侧 |
|---|---|---|
| 执行形态 | Python + 动态分发，可在线修改 | 提前编译成离线模型文件，运行时只做推理 |
| 调试手段 | 进程内挂 hook、插同步点、改代码重跑 | 要么在转换阶段查，要么只能看输入输出 |
| 形状 | 动态，靠分桶或图捕获应对 | 多数情况编译期固定 |
| 量化 | 可选的优化手段 | 基本是必选项，否则放不下 |
| 显存 | 几十 GB，瓶颈是带宽 | 几百 MB 到几 GB，瓶颈是容量本身 |
| 约束条件 | 吞吐与延迟 | 外加功耗、发热、冷启动时间、安装包体积 |
| 算力分配 | 整卡独占 | 与系统其他应用争抢，可能被降频或杀死 |

最后两行是端侧独有的。云侧优化的目标函数是「在给定硬件上跑多快」，端侧的目标函数里还有「持续跑十分钟手机烫不烫」「模型文件会不会让应用包超过商店限制」。这些约束会反过来决定模型结构的选择，而不只是部署方式的选择。

**结论是：把云侧 skill 改写成端侧版本，改出来的东西不会对。** 不是文字要换，是整个工作流要重新设计。

## 如果你确实要做端侧

那它是一个独立的能力体系。下面列出它真正需要覆盖的事，供你判断规模。

**模型转换与算子覆盖度核查。** 端侧部署的第一道关是把训练好的模型转成端侧运行时能加载的格式，而转换失败的最常见原因是某个算子不被支持。这件事要在立项时就查，不能等模型训完再查。方法论上最重要的一条：**先拿目标模型的算子清单去对端侧运行时的支持列表，再决定模型结构**，反过来做会在项目后期被迫改模型。

**不支持算子的处置。** 每个不支持的算子有四条出路：用支持的算子组合等价替换、回退到 CPU 执行（要算上来回搬数据的代价，频繁回退会比全 CPU 还慢）、自己写算子实现、改模型结构绕开。选哪条取决于这个算子在图里出现的位置和次数——出现在主干上且次数多的，只能写实现。

**量化与精度验收。** 端侧量化通常比云侧激进（int8 甚至更低），且往往要做逐通道校准。这里唯一能和云侧共享的方法论是**精度验收不能只看单个指标**：要同时看任务指标（准确率/困惑度）和逐层数值偏差，因为逐层偏差小不代表任务指标不掉，任务指标在小样本上不掉也不代表线上不掉。

**真机实测。** 端侧没有「模拟器上测一测就行」这回事。功耗、发热降频、与其他应用争抢资源，这三件事只有真机长时间运行才会暴露。典型现象是：冷启动跑分很漂亮，连续推理三分钟后降频一半。验收必须包含持续负载测试。

**异构回退路径。** 端侧设备通常同时有 CPU、GPU 和专用神经网络加速单元，同一个模型在不同机型上可能走不同路径。要设计明确的回退顺序和降级策略，并在低端机型上验证。

## 哪些东西是真能共享的

有两样，但都不足以构成复用一个 skill 的理由。

**量化的精度验收方法论。** 「怎么证明量化后模型还能用」这件事，云侧和端侧的判据是相通的。这部分内容在[量化接入](quantization.md)里，端侧可以引用。

**对比驱动的数值排查。** 「拿一个可信实现当标杆，逐层对比找第一个偏差点」这个方法在哪都成立。区别是端侧做逐层对比要在转换工具链里做，不是在 PyTorch 里挂 hook。

## 需要你拍板的问题

| 问题 | 回答后能解锁什么 |
|---|---|
| 你有端侧产品线吗，或者近期有计划吗？ | 这一个问题就能决定本领域是否立项，其余问题都在它之后 |
| 如果有，端侧用的是同一款自研芯片的精简版，还是完全不同的硬件？ | 同源的话算子库和编译器可能部分共享，否则是彻底独立的两条栈 |
| 端侧跑的是大语言模型，还是传统的视觉/语音小模型？ | 两者的工具链、量化策略、内存管理方式差别很大，不能合成一套 skill |

如果第一个问题的答案是否，建议**直接关闭这个领域**，把文档留在这里作为决策记录即可。

## 知识来源

- 端侧推理的约束维度（功耗、发热降频、包体积、冷启动）与真机实测的必要性：移动端 AI 部署的公开工程实践共识

- 端侧量化的逐通道校准与精度评估：训练后量化（PTQ）的公开文献与上述工具链的量化文档
- 云侧与端侧在执行形态上的根本差异（动态分发 vs 提前编译）：PyTorch eager/compile 执行模型与移动端推理引擎公开设计文档的对比
